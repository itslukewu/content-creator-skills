# topic-finder（中文版）

本文件供中文用户使用，内容与上一级目录的英文版 `SKILL.md` 一致。两个版本只需安装其中一个。

## 输入与输出

- **输入**：一份 config（格式见同目录的 `config.example.yaml`）；可选：已有选题库。
- **输出**：一张候选选题表。每条带可点击的来源链接和内容准备度。用户确认后才写入任何外部系统。

## 流程

```text
读取 config
    ↓
是否已有可复用的受众画像？
    ├─ 没有 → 第一步：从对标内容反推初始受众画像
    └─ 已有 → 复用画像，跳过第一步
    ↓
第二步：收集候选选题（栏目定向找题 + 开放找题）
    ↓
第三步：筛选与去重
    ↓
第四步：输出选题表 → 用户确认 → 写入选题库
```

## 开始前

1. 读取 config。
2. 没有 config 时，先向用户确认三件事：
   - 有哪些受众或对标线索（对标账号、内容样例都可以）
   - 有哪些固定栏目（可以没有）
   - 有哪些可用来源，以及怎么访问

   用户还没确定受众，不影响开始：只要有对标线索，就进入第一步。不替用户编造这些信息。
3. 三个时间概念分开处理，互不替代：
   - **用户明确选择的目标受众**（`source: user_defined`）：不因时间过去而失效，也不会被反推结果替换。新证据只补充观察。
   - **从数据反推的画像**（`source: inferred`）：到 `review_every_days` 时提醒复查，可以按新证据更新。
   - **对标帖子回看窗口**（`lookback_days`，默认 90）：只决定取多久的帖子，与画像有效期无关。

## 共用规则：相对表现（RP）

第一步和来源 A 都用这套规则。

- **RP** = 该帖点赞 ÷ 该账号在同一窗口内可见点赞的中位数。
- 隐藏或缺失的点赞不当成 0：既不进基线，也不计算 RP。
- 账号的可见点赞帖少于 `min_baseline_posts`（默认 5），或基线为 0 时，不计算该账号的 RP。
- RP ≥ `outlier_rp`（默认 2）的帖子算突出帖。
- **主题突出比例** = 该主题的突出帖数 ÷ 该主题全部可算 RP 的帖子数。不能只在突出帖里统计。
- 每次运行都记录：时间范围、抓取日期、有效帖子数、各账号基线，以及被排除的账号和原因。
- 评论数会被「评论关键词领资料」放大。判断内容反馈以点赞为主，评论单独说明。
- 这些数字只说明某主题「在本轮对标样本中」表现如何。表现一般不等于市场供给过剩，也不能据此否决一个新的切入点。

## 第一步：反推初始受众画像

没有可复用画像时，默认执行这一步。

目的：从有内容依据的观察出发建立初始画像，而不是先假设受众再找证据。画像描述的是「这些内容在服务谁」，不代表对标账号真实粉丝的人口构成。

1. 获取对标数据。与来源 A 共用同一批，不重复抓取。
2. 按共用规则计算 RP、找出突出帖，按主题归类并计算主题突出比例。
3. 从突出帖的内容反推：内容在帮谁、解决什么问题、承诺什么结果。
4. 每个画像分两层写：
   - **观察**：能从帖子内容直接看出的。附证据帖链接，注明涉及几个账号。
   - **待验证假设**：年龄、收入、付费意愿、职业，以及动机和所处阶段。帖子里有本人直接自述的，标「自述」并附链接；由内容推断的，标「推断」。
5. 某个结论只来自一两个账号时，要标明。

**产出**：3 到 6 个初始画像，写回 config 的 `audience` 段，标 `source: inferred`，记录生成日期和数据窗口。用户确认后，可以改为 `user_defined`。

## 第二步：收集候选选题

两种找法同时进行。这是两种找题方式，不是两类来源：

- **栏目定向找题**：对 config 里的每个固定栏目，按它的 `brief` 主动检索素材，比如工具、场景、案例。没有固定栏目时跳过。
- **开放找题**：从各路来源发现其他值得讲的内容，不要求归入固定栏目，归属可以是「开放选题」。

默认综合使用 config 里所有可用的来源。用户限定了来源，或某个来源无法访问时，用剩下的来源运行，并在输出开头写明本轮覆盖了哪些来源、缺了什么、为什么。不为凑齐来源编造材料。

### 来源 A：对标账号的突出内容

- 按 `lookback_days` 独立读取或更新对标数据。第一步本轮已取得同一批数据时直接复用。
- 用共用 RP 规则找突出帖。突出内容只要适合目标受众就可以采用，不要求用户有相同的经历。
- 借鉴的是主题、切入角度、结构和表达形式，不照搬对方的脚本、观点、案例和素材。

### 来源 B：受众与市场信号

- **调查与报告**：记录已披露的样本量、受访人群、调查方法和调查时间；没披露的写「未披露」，不补造。二手汇总标「二手来源」，能找到原始报告就追到原始报告。
- **社区、论坛、问答、评论、产品评价**：保留原话、情境、链接和时间。区分真实提问、经验反馈、一般赞美和领取资料。不把一句抱怨扩大成整个群体的共识。
- **搜索联想**：只用来发现大家怎么表达、找检索线索，之后再追查具体材料。
- 搜索词按受众的身份、活动和目标来写，不把预设痛点写进搜索词。工具名可以作为入口，但不是必填。

### 来源 C：用户收藏

- 读取 config 指定的收藏位置。每条收藏先判断用途：
  - **选题线索**：主题、问题、观点、案例
  - **制作参考**：结构、钩子、视觉、剪辑。保留为参考，不强行生成选题
- 有用户备注时优先参考；没有备注时，不推测收藏动机。
- 视频尽量获取转写。依赖画面的内容，还要查看视觉材料（封面、截图、画面描述）。获取失败时，注明实际读到了什么、缺什么，不假装已经看完；其他来源照常进行。抓取工具见 config 的 `tools`。
- 收藏的标题或文案与实际内容不一致时，标出来。

每条候选都要记录：
- 发现来源和链接（可以有多个）
- 栏目归属
- 可用素材（包括用户的亲身经历、自己的数据、实测结果，如果有）

## 第三步：筛选与去重

每条候选回答五个问题：

1. **适合谁？** 至少对应一个目标受众：一个主要受众，可以再加次要受众。
2. **为什么值得为这类受众讲？** 依据是突出反馈、市场信号、具体用途，还是用户收藏中的观点与案例？不同依据分别说明。「已经有高互动」不是统一门槛。
3. **能给目标受众带来什么具体价值？准备采用什么切入点？有哪些素材可以增强它？** 清楚的解释、有用的整理、案例拆解或演示都能让一条内容成立，不需要每次都有别人没有的发现。亲身经历、自己的数据和实测结果是加分项，不是任何来源的准入条件。
4. **关键主张站得住吗？** 哪些事实、数字、功能需要核对？他人的案例、官方演示和用户的实测分开标注，不能互相冒充。
5. **制作需要什么？** 素材现成，还是需要测试、拍摄或补资料？制作条件与选题价值分开判断。

### 去重

- 本批候选之间，以及本批与已有选题库之间，都按「讲的问题 + 切入角度」判断是否重复。不能只看标题或 URL。
- 同一话题、同一角度：合并成一条，来源和链接并入。
- 同一话题，但服务不同受众或回答不同问题：分开保留。
- 同一份材料被多处转发，只算一份依据。

### 内容准备度

每条候选给一个：

| 状态 | 含义 |
|---|---|
| 可写 Brief | 已有足够依据形成 Brief，之后再展开脚本 |
| 待核实 | 有潜力，但影响核心论点的事实或数字还没核对。列明要核实的事项 |
| 待测试 | 选定的表达依赖实际运行结果，比如要讲实测效果，测试后才能作出相应主张。只介绍官方功能或解读公开案例的，不需要测试 |
| 放弃 | 不适合目标受众、缺乏具体价值、关键主张无法支撑，或与已有选题的问题和角度实质重复。写明理由 |

「该主题在对标样本中表现一般」不是放弃的理由。

## 第四步：输出选题表

先把表给用户看。每条包括：

- 选题／暂定标题
- 主要受众（有次要受众也写上）
- 发现来源与链接：一个或多个可点击的链接，标明来自哪路来源
- 栏目归属：某个固定栏目，或「开放选题」
- 为什么值得做：依据、出处、局限
- 内容切入点：核心观点、案例或演示场景；建议形式；可结合的个人素材（有就写）
- 内容准备度 + 下一步

表格开头写一段运行说明：
- 数据窗口
- 各来源的覆盖情况，以及缺失或降级
- 本轮是否复用了已有画像

### 写入选题库

- 用户确认后才写入。写完报告写了几条、写在哪里。
- 写入前先读取数据库的实际字段，按字段类型映射。字段不支持链接时，把链接写进文本字段，并告诉用户。
- **内容准备度**（可写 Brief／待核实／待测试）和**审批或工作流状态**（比如「待确认」）分开存放，互不覆盖。新条目的工作流状态用 config 里的默认值。config 设置了 `readiness_labels` 时，写入时使用其中的标签。

## 不要做的事

- 不编造链接、播放量、数据或报告字段。拿不到就写「待补」或「未披露」。
- 不把推断出来的受众特征写成结论。
- 不用对标样本的表现去判定整个市场的供需。
- 不把他人的案例或官方演示写成用户自己的实测。
- 未经用户确认，不写入任何外部系统（数据库、GitHub 等）。
